# LabelForge AI — Annotation Intelligence Lab

**Independent portfolio project | Intermediate level | Version 1.0**

LabelForge AI is a reproducible data annotation and quality-assurance project using a synthetic customer-support dataset. It demonstrates label taxonomy design, guideline writing, structured annotation, schema validation, error reporting, and evaluation metrics.

> **Transparency:** The records are synthetic and were authored for this portfolio demonstration. The project has not been externally validated. Metrics should be generated by running the included code; do not claim model improvement or real-world impact.

## Project goals
- Produce consistent intent, sentiment, urgency, and review-routing labels.
- Document operational definitions and edge-case decisions.
- Validate labels and dataset structure programmatically.
- Generate a data-quality report with counts and checks.
- Provide a reproducible starting point for independent annotation or second-reviewer agreement.

## Independent annotation and reference comparison
Independent annotation and reference comparison

The 60-row data/unlabeled_batch.csv contains my independent annotations for four fields: intent, sentiment, urgency, and review_required. The annotations were completed using guidelines/annotation_handbook.md before comparison with the reference dataset.

To reproduce the comparison, run:

python src/compare_to_reference.py \
  --annotations data/unlabeled_batch.csv \
  --reference data/annotation_dataset.csv \
  --output-dir reports/reference_comparison

The current reference-comparison report records 60/60 exact matches for each of the four fields, with zero disagreements and 100% observed agreement with the reference labels. The comparison also reports 60/60 rows valid for each field.

Important interpretation: annotation_dataset.csv contains synthetic, authored reference labels, not independently verified ground truth. These results measure agreement with that reference—not objective correctness, model performance, or inter-annotator reliability. The perfect agreement should be interpreted cautiously and does not establish that the annotation process is error-free.

The output files include agreement_report.md, field_agreement.csv, disagreements.csv, confusion_matrices.csv, validation_issues.csv, and validation_report.json. Review any future mismatches against the handbook and document adjudication decisions rather than silently changing labels.

### Optional: compare two independent reviewers
For a future real inter-annotator agreement study, use two separate annotation files completed independently by two reviewers. Start with data/annotator_a_template.csv and data/annotator_b_template.csv. Give both reviewers the same source messages without revealing one another's labels. Save their completed files as data/annotator_a.csv and data/annotator_b.csv.
Current demonstration status: The comparison script has been tested using 60 synthetic source records and two simulated annotation files. The workflow completed with zero validation issues and generated field-level agreement metrics, Cohen's kappa, confusion matrices, and disagreement reports. These results demonstrate the software workflow only; they are not real inter-annotator agreement results.
To reproduce the simulated test, run:

py src/compare_annotations.py \
  --source data/unlabeled_source.csv \
  --annotator-a data/simulated_annotator_a.csv \
  --annotator-b data/simulated_annotator_b.csv

For a future study using real independent reviewers, use the completed reviewer files and the appropriate source dataset instead. Cohen's kappa may be mathematically undefined when there is no label variation; the script reports this transparently.

## Worked example
Text: “The delivery was late, but the product works perfectly.”
- intent: `shipping`
- sentiment: `mixed`
- urgency: `medium`
- review_required: `no_review`

Rationale: shipping is the primary issue; the message expresses both a negative delivery experience and positive product assessment. There is no high-urgency trigger.

## Recommended evaluation plan
1. Validate all rows with the included script.
2. Randomly select 15–20 records for a blind second annotation.
3. Compare each label field separately.
4. Review disagreements and update the handbook only through documented adjudication.
5. Re-run validation and record the version of the guidelines and dataset.
6. Report observed metrics with the sample size and limitations.

## Limitations
- Small, synthetic, English-only sample.
- Class distributions are not representative of real support queues.
- Labels reflect a custom portfolio taxonomy.
- Urgency is a demonstration label, not a validated service policy.
- No production model has been trained or improved by this repository.
