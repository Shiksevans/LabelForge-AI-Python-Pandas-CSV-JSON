# LabelForge AI — Annotation Intelligence Lab

**Independent portfolio project | Intermediate level | Version 1.0**

LabelForge AI is a reproducible data annotation and quality-assurance project using a synthetic customer-support dataset. It demonstrates label taxonomy design, guideline writing, structured annotation, schema validation, error reporting, and evaluation metrics.

> **Transparency:** The records are synthetic and were authored for this portfolio demonstration. The project has not been externally validated. Metrics should be generated by running the included code; do not claim model improvement or real-world impact.

## Project goals
- Produce consistent intent, sentiment, urgency, and review-routing labels.
- Document operational definitions and edge-case decisions.
- Validate labels and dataset structure programmatically.
- Generate a data-quality report with counts and checks.
- Provide a reproducible starting point for independent annotation or second-reviewer agreement.

## Quick start
Requires Python 3.10+.

```bash
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1

pip install -r requirements.txt
python src/validate_dataset.py --input data/annotation_dataset.csv --report reports/quality_report.json
python -m unittest discover -s tests -v
```

The validator checks required columns, missing values, duplicate IDs, empty text, invalid label values, and label distributions. It writes a JSON report and exits with a non-zero status if validation errors are found.

## Dataset schema
| Field | Type | Description |
|---|---|---|
| record_id | string | Unique synthetic record identifier |
| text | string | Customer-support message |
| intent | category | Primary issue category |
| sentiment | category | Overall expressed sentiment |
| urgency | category | Simulated routing urgency |
| review_required | category | Whether a human should review the case |

Allowed labels are documented in `guidelines/annotation_handbook.md`.

## Quality metrics
The validator calculates:
- Total rows and unique IDs
- Missing-value and empty-text counts
- Duplicate ID count
- Invalid-label counts by field
- Label distribution by field

For annotation agreement, label a separate copy independently or ask a second reviewer to annotate the same sample without seeing the original labels. Then compare per-field agreement or Cohen's kappa. Do not use agreement with the authored labels as proof of independent inter-annotator reliability.

## Worked example
Text: “The delivery was late, but the product works perfectly.”
- intent: `shipping`
- sentiment: `mixed`
- urgency: `medium`
- review_required: `no_review`

Rationale: shipping is the primary issue; the message expresses both a negative delivery experience and positive product assessment. There is no high-urgency trigger.

## Recommended evaluation plan
1. Validate all rows with the included script.
2. Randomly select 15–20 records for a blind second annotation.
3. Compare each label field separately.
4. Review disagreements and update the handbook only through documented adjudication.
5. Re-run validation and record the version of the guidelines and dataset.
6. Report observed metrics with the sample size and limitations.

## Limitations
- Small, synthetic, English-only sample.
- Class distributions are not representative of real support queues.
- Labels reflect a custom portfolio taxonomy.
- Urgency is a demonstration label, not a validated service policy.
- No production model has been trained or improved by this repository.
